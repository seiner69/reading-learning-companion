# 阅读与学习伴读 Skill

面向希望让 AI 带着读材料、理解概念并逐步学会使用的人。支持中文逐页/逐章伴读、按需跨学科分析、复述纠错与迁移练习，以及确认后的结论整理。

核心不是让讲解更长，而是避免三种错位：把泛泛讲课当伴读，把答对一题当掌握，把顺口结论当成无条件真理。

## 亮点

- 跟随指定材料、当前锚点与最新阅读节奏，区分文件页序和印刷页码。
- 将原文、解释、外部补充和推测分开，不用类比代替证据。
- 先提供知识输入，再按需检查理解；只评价实际观察到的表现。
- 跨学科视角服务于当前问题，不强行堆叠学科或预设书单。
- 结论先提候选，确认与文件归档分别处理，“继续”不等于确认。
- 可以只听讲、暂不练习；不会自行创建课程、定时提醒或学习档案。

## 前置条件

使用支持 Skill 指令的代理环境。需由使用者提供有权使用的材料，或提供代理可读取的文件/链接；涉及图片、PDF、网页时，环境还需要对应读取能力。

本仓库只提供方法说明，无运行脚本、服务、模型、API 密钥或书籍内容，不依赖特定第三方插件。是否能读图、写文件或保留跨会话进度，取决于使用环境和授权。

## 使用方式

### 不安装，先在新任务试用

下载或克隆仓库：

~~~sh
git clone https://github.com/seiner69/reading-learning-companion.git
~~~

在一个新的任务中附上本仓库的 SKILL.md，说明按文件中的方法处理所提供材料。需要某个模式时，让代理读取对应的 references 文件。这样不会把它安装成其他任务自动发现的 Skill。

例如：

> 按附带 Skill 的方法带我阅读这份材料，从我指出的位置开始，每次两页。先做忠实伴读；扩展解释单独标注，今天不做练习。

### 可选安装

只有你希望在 Codex 中长期使用时，再把完整的 reading-learning-companion 文件夹放进个人技能目录 .codex/skills，并按所在环境的技能发现机制加载。不要覆盖同名的已有文件夹；先比较内容。

本次制作和发布没有执行安装，原有阅读任务、材料、笔记和进度均未修改。安装之后环境可能根据描述自动选用 Skill；是否安装由使用者决定。

安装后可显式使用：

> 请使用 $reading-learning-companion，按当前材料和已约定位置继续阅读，不改变现有节奏。

跨学科学习可这样提出：

> 带我理解这一小节，先解释作者实际的命题，再用一个相关学科的视角分析它；说明类比在哪里失效。讲完后给我一道迁移题，先不要公布答案。

结论整理可这样提出：

> 这一节结束后，给一条压缩结论和适用边界；先标为待确认。我确认后才保存到我指定的笔记，不确认也可以继续阅读。

## 目录结构

~~~text
reading-learning-companion/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── source-reading.md
│   ├── learning-methods.md
│   └── confirmed-notes.md
├── evals/scenarios.md
└── README.md
~~~

SKILL.md 负责目标、方式选择与共享边界；references 按所需方式读取；evals 是虚构材料与可观察验收条件。

## 验证方式

- 检查 SKILL.md 的 YAML frontmatter、名称、引用文件是否有效，所有文件应为 UTF-8 文本。
- 用 evals/scenarios.md 中的夹具在独立新任务逐条演练，观察页码、来源标注、学习评价、确认与写入边界。
- 文件写入场景只使用隔离的临时目录和虚构笔记；不得用正在阅读的真实资料做破坏性实验。
- 本次做了结构校验与 12 个合成场景的人工走查；这不是独立模型行为评测，也不保证每个模型都会遵守所有指令。

如你的环境有 skill-creator，可使用它的 quick_validate.py 校验格式；它只能检查结构，不能证明教学质量。

## 已知限制

- 不替代教材、原始证据、教师或专业资格，不能保证学习效果。
- 不自动读取 Codex 全部历史，也没有持久记忆；继续已有学习需要当前上下文或用户提供的检查点。
- 对正文不能访问、OCR 缺失、版本不同和页码不明的情况，需要先补材料或核对定位。
- 跨学科类比和历史案例需要事实核验，不能自动升级为科学结论。
- 归档依赖代理的实际文件工具；指令层的确认约束不等于数据库事务或程序级权限控制。
- 本仓库不提供受保护作品的全文、逐页翻译集合、私人阅读记录或第三方 Skill 副本。
